# M3 Database tab — UI spec

Date: 2026-10-16 — Design note: [design/m3-drift-inspector.md](../design/m3-drift-inspector.md) — Status: approved by PM 16 Oct 2026

Builds on [ui/m2-dashboard.md](m2-dashboard.md): same header, tokens, breakpoints, focus rules and copy style. The Database tab becomes the first tab: **Database · Logs · Activity**.

## User and task

- User: a Flutter developer whose app uses Drift, working in Claude Desktop.
- Task: see what the app saved, find rows fast, run a quick SQL query, see what an action changed, and (rarely, on purpose) fix a row.
- Success: a new row appears and flashes within 1 s; any table opens in under 1 s; a SQL query runs with Cmd/Ctrl+Enter; "what changed" takes two clicks (Snapshot, then Diff); no write happens without a visible confirm.

## Flow

```mermaid
flowchart LR
  T[Database tab] -->|no database| S[Setup help: add flutterdeck_drift, or Snapshot on Android]
  T --> L[Database + table list]
  L --> V[Table view]
  V --> R[Row details]
  V -->|Diagram| G[Schema diagram]
  L --> Q[SQL editor]
  Q -->|refused by the guard| E[Reason shown, nothing ran]
  Q --> RS[Result grid]
  L --> P[Snapshot] --> D[Diff view]
  V -->|writes on| W[Edit → SQL preview → Confirm]
  W -->|cancel| V
```

## Breakpoints

- 320 px: pickers stack full width; view switcher becomes a select; grid shows first 2 columns + "more" (row details for the rest); diagram is list-style (table → columns → links) instead of boxes.
- 420 px: layout above.
- ≥ 900 px: sidebar of tables (240 px), view fills the rest; diagram as boxes.

## Accessibility notes

- Grid uses the ARIA grid pattern (`role=grid`, row/column headers, arrow-key cell navigation, `aria-sort`); not every one of 10,000 rows in the DOM (virtualised) with `aria-rowcount`.
- Flash is also announced politely once per batch: "3 rows added to orders" (not per row).
- Diff uses words and symbols (+ added, ~ changed, − removed), not colour alone.
- The SQL editor has a visible label "SQL", and the run shortcut is in the Run button's `aria-keyshortcuts`. Tab moves focus out of the editor (no indent on Tab), so there is no keyboard trap (SC 2.1.2); Escape also leaves the editor.
- Confirm dialog: `role=alertdialog`, focus trapped while open, returns to the trigger.
- The diagram has pan buttons (↑ ↓ ← →) besides dragging (SC 2.5.7). Sticky header and footer use scroll padding so a focused cell is never hidden (SC 2.4.11).
- Diagram boxes are focusable buttons with names "orders table, 4 columns, links to customers"; the 320 px list version is the accessible alternative for screen readers at all sizes (a "List view" toggle).
- Targets ≥ 24×24 px; contrast checked from tokens in both themes (green/amber/red diff colours meet 4.5:1 for text).

## Copy

- Setup: "Add flutterdeck_drift to see your database live." · "In your app's main(), after you create the database: `FlutterDeckDrift.register(db, name: 'app');` It does nothing in release builds."
- Snapshot banner: "Snapshot from 14:02 — this is a copy, not live. Refresh"
- Guard refusal: "Only reading queries run here. This one would change data (<reason>)." Reasons: "it deletes rows", "it adds a database", "it changes a setting", "it has more than one statement".
- Writes off (when asked): "Changing data is off. Turn it on with db.allowWrites in .flutterdeck/config.json."
- Writes on pill: "Writes on" (from config) — tooltip "Every change still asks you first".
- Confirm: "Run this change?" · "Database: <name>" · "Table: <name>" · "Run change" · "Cancel" · lost connection: "Lost connection; the change did not run" · answered elsewhere: "Answered in another tab". (Database line: lead decision, 17 Oct 2026.)
- Row changed meanwhile (review L3): Edit and Delete row from row details only change the row as it was read. Edit also matches each edited column's old value, and Delete matches every column shown (`IS ?`, so nulls match; a blob by its type, size and the bytes sent). The confirm shows the whole SQL. When no row matches: "This row changed since you opened it. Reload it and try again." with a "Reload row" button. The form keeps what the user typed until then. An edit sends at most 999 values (the Drift package's cap): past it, the blobs' bytes are left out of the check first (type and size stay), and if it still doesn't fit, nothing is asked and the panel says "This table has too many columns to check the row safely; edit it with SQL in your own tools."
- Add row (toolbar, writes on, live backend): "Add row" (lead decision, 17 Oct 2026); the form's heading "<table>: new row".
- Rows that can't be edited: Edit and Delete row are disabled, and their tooltip says why: "This row has no primary key to find it by" · "Its primary key is null, which can match more than one row" · "Its primary key can't be sent: it is a blob or an odd number".
- Foreign-key filter: "Showing <table>.<column> = <value>" · "Clear filter".
- Device picker (choose-device): the daemon's message ("More than one Android device could be running this app. Pick the one to copy from." or "The app is on more than one booted iOS simulator. Pick the one to copy from.") · label "Device" · "Use this device".
- An edit the gate refuses (for example the trigger rule) also logs "Write denied: <table>" (lead decision G4).
- Activity entries: "Snapshot taken: <database>" · "Diff shown: <database>" · "Write allowed: <tables>, N row(s) changed" · "Write denied: <tables>" · an edit from row details that matched no row because the row changed (review L3): "Write denied: <table> (row changed)", never "0 rows changed". The tables are the one the edit writes, not tables it only reads for a foreign-key check. Names only, never SQL or values.
- Claude never writes: Claude's chat may contain SQL; the SQL editor runs reading queries only; changes are made in the row-details editor, with writes on and a confirm.
- Snapshot busy: "The app is writing; try Refresh." · iOS on Linux/Windows: option hidden.
- Diff empty: "No changes since 14:02."
- Hidden column cell (dashboard shows real data; this copy is for Claude-facing output only): "[hidden]".

## Fake mode (PM checks)

- The fake app adds an order every 5 s up to order 500 (about 40 minutes), so the live-flash steps still work late in a PM check (lead decision, batch 4 QA).

## Tokens used

As M2, plus `color.diff.added`, `color.diff.changed`, `color.diff.removed` (text and 12% tint backgrounds, both themes), `color.flash` (row flash tint), `font.mono` for SQL and cell values.
