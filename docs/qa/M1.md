Finding: after any hot reload, a breakpoint that a VM service client set before the reload stops pausing the app. The VM still lists it as resolved, and no `BreakpointRemoved` event comes. Removing it and setting it again fixes it. This also happens without the daemon, and also with a reload that changes no source (a one-off scratch run on 2026-10-13, not part of the committed script). The Dart debug adapter (`dds` 5.3.0, `isolate_manager.dart`) sends breakpoints again only after a hot restart (`PausePostRequest`), not after a hot reload. So a real IDE may see the same thing after its own hot reload. The PM check shows what Android Studio does.

PM decision, 14 Oct 2026 ([PLAN.md](../PLAN.md#m1--core-daemon-and-attaching-to-running-apps) M1 Accept line): a breakpoint that does not pause after a hot reload is an upstream Flutter limitation and is not part of the check.

Minor: `GET /api/apps` returns no `device` for an app before attach (shown as `(?)` above), so a client can't tell Android from iOS until it attaches. It doesn't block this criterion.

### Observations (not failures)

- **README step 5 and Android Studio's reload on save.** The README says "Edit `reloadMarker` … save, then reload through the daemon". Android Studio hot reloads on save by default, so the new text can come from the IDE, not from the daemon's reload. The PM check below edits the file from the terminal so the daemon's reload is what changes the screen. Whether an external edit also triggers the IDE reload was not observed (no IDE here).
- **README step 6 can miss the tap lines.** `limit=10` returns the newest 10 entries from all sources. On this fresh emulator, 7 of 10 were Android system lines (`ActivityThread`, GC). After a busy minute the `Tap N` lines can drop out. `&text=Tap` returns only the tap lines. Suggest the README use it.
- `startedBy` is `"unknown"` and `device.id` is `"unknown"` for an app started by `flutter run`. Not in the criteria.

### Not observed

- The real IDE breakpoint and the Android Studio reload-on-save behaviour: needs the PM's Android Studio (PM check below).
- `git switch main && git pull` in PM step 1: the branch is not merged yet. QA ran `pnpm install && pnpm build` on the branch.
