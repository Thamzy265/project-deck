## PM check

Before you start: Claude Code CLI installed, this branch checked out in a folder you can use, about 5 minutes.

1. Optional: remove the old plugin. Skip this step if you never installed flutterdeck.

```bash
claude plugin uninstall flutterdeck@flutterdeck-dev
```

Expected: the old plugin is removed. If it says "not found", it was already gone: continue.

2. In the Pitdeck checkout folder, remember its path, add the marketplace from it and install the new plugin. Use the same terminal window for the next steps, so `PITDECK_DIR` stays set.

```bash
PITDECK_DIR="$(pwd)"
claude plugin marketplace add "$PITDECK_DIR"
claude plugin install pitdeck@pitdeck-dev
```

Expected: both commands succeed and say `pitdeck` was installed. If you see an unknown-plugin error, tell the lead.

3. Go to a Flutter project with Drift (`cd <your Flutter project>`), with the app running from your IDE, start the dashboard and a new Claude session there.

```bash
node "$PITDECK_DIR/packages/cli/dist/main.js" start
```

Expected: "Pitdeck started." and an address.

4. In the new Claude session type:

```text
/db how many orders are pending?
```

Expected: Claude uses the `pitdeck` MCP tools (`db_list`, `db_query`) and answers with a number. If the tools are listed as `flutterdeck`, redo step 1.

5. Clean up.

```bash
node "$PITDECK_DIR/packages/cli/dist/main.js" stop
```

Expected: "Pitdeck stopped."

PM check steps: not run by QA from a clean Claude profile (needs the PM's profile). Steps 3 and 5 use commands QA ran in criterion 1 and 2.

`src/smoke-plugin-step.test.ts > the tarball smoke script, plugin step > passes for a package at the pinned version, fetched only from the loopback registry` fails on `check (windows-latest, 22)` and `(windows-latest, 24)` (run 44507131850, commit ae7cea8). The same smoke script run directly (`tarball-smoke` job, windows) passes.

- Observed (Node 22): `plugin .mcp.json: npx -y pitdeck@0.1.0 mcp  FAIL  initialize: no answer in 60000 ms … npm error 404 Not Found - GET https://registry.npmjs.org/pitdeck`. So npx asked the public registry, not the loopback one. On Node 24 the same row fails after 60 s with an npm warning "Unknown env config npm-globalconfig".
- Expected: only 127.0.0.1 is contacted.
- Repro: `pnpm test` on Windows (CI), or the one test under pnpm. Not reproduced by QA: no Windows machine.
- Hypothesis, not confirmed: the test runs under pnpm, which puts its own `npm_config_registry` (and `npm_config_globalconfig`) in the environment. `scripts/smoke/tarball.mjs` builds the child env with `{ ...process.env }` and then adds `npm_config_registry: registry.url` (line ~424). On Windows environment names are case-insensitive, so two keys that differ only in case can both exist in the object, and the child may get the earlier value. Fix idea: delete every key that matches `/^npm_config_/i` from the copy before adding the loopback ones, then set them. It matters beyond CI: a developer's `NPM_CONFIG_REGISTRY` would make the smoke contact a real registry. Security note: the step then sends a request to the public registry for a name the project may own, so the smoke test must not depend on env case.

### PM check (batch 3)

Only after the merge and the npm publish (batch 7). Nothing can be done before: the public marketplace entry fetches `main`, and `pitdeck@0.1.0` is not on npm yet.

Before you start: the branch is merged, `pitdeck@0.1.0` is on npm, Claude Code is installed, about 5 minutes. Use your real Claude, because this checks the real install.

1. Add the marketplace.

```bash
claude plugin marketplace add Thamzy265/project-deck
```

Expected: "Successfully added marketplace: pitdeck". If you see an authentication error, run `export CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1` and repeat.

2. Install the plugin.

```bash
claude plugin install pitdeck@pitdeck
```

Expected: "Successfully installed plugin: pitdeck@pitdeck". If it asks to trust the folder or the marketplace, answer yes.

3. In your Flutter project, set up Pitdeck, then start Claude there.

```bash
cd <your Flutter project>
npx -y pitdeck@0.1.0 init
claude
```

Expected: `init` lists the Dart and Flutter versions and prints the same two `claude plugin` commands. In Claude, `/mcp` lists `plugin:pitdeck:pitdeck` and `plugin:pitdeck:dart` as connected. If `pitdeck` shows as failed, copy the message and send it to the lead.

4. With your app running from your IDE, type `/pitdeck:check`.

Expected: a short report (reload result, runtime errors, logs, database changes) and your IDE breakpoint still hits.

5. Clean up (only if you do not want to keep the plugin).

```bash
claude plugin uninstall pitdeck@pitdeck
claude plugin marketplace remove pitdeck
```

Expected: both print a success line.

Verified by QA: no. These steps need the PM's real Claude, the GitHub install and the published package, none of which exist yet. QA ran the same commands against a `file://` clone in a scratch config (criterion 2).
