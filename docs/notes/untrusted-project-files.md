# Untrusted project files

Date: 2026-10-15. Source: review finding R1 on `feat/mcp`.

A project folder can come from a cloned repository, so everything under its `.flutterdeck/` is untrusted. Anything there may be a symlink to one of the user's own files, a folder, or a crafted file. FlutterDeck never follows a link there, and never repeats file content in an error.

| File                                         | Read / write                                      | Protection                                                                                                                                                                                                                                 |
| -------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.flutterdeck/` itself                       | both                                              | `checkStateDir` (lstat) refuses a link or a file. The daemon won't start, and the MCP server answers with the reason without starting a daemon.                                                                                            |
| `.flutterdeck/config.json`                   | read (daemon, MCP server)                         | `readRegularFile`: O_NOFOLLOW, or lstat on Windows; regular files only; 8 MB cap. Invalid JSON gives a fixed message, never the parser's (which quotes the text). A bad `version` isn't quoted.                                            |
| `.flutterdeck/runtime.json`                  | write (daemon), read (daemon, MCP server)         | Written to a new temp file (`wx`), then renamed over the old one, so a link is replaced, never followed. Read with `readRegularFile`; a link or a folder means "no daemon".                                                                |
| `.flutterdeck/startup.lock`                  | write and read (daemon)                           | Created with `wx` (O_EXCL refuses links). A link found there is removed (the link itself, never its target). It is read with `readRegularFile`, and its age comes from `lstat`. Stale locks are renamed aside before they are removed.     |
| `.flutterdeck/daemon.log`                    | write (MCP server spawn), read (MCP server)       | Whatever is there is removed, then the log is created with `wx`, mode 0600. A folder there means no log. It holds the daemon's stderr only. Its last line is read with `readRegularFile`, paths are hidden, and then it is cut and masked. |
| `.flutterdeck/*.tmp`, `startup.lock.*.stale` | write (daemon)                                    | Random names, created with `wx`. Clean-up uses `lstat` and removes links themselves.                                                                                                                                                       |
| `~/.flutterdeck/ports.json`                  | write (daemon, `init`), read (daemon, MCP server) | Written whole to a temp file, then linked or renamed into place. Read with `readRegularFile`; a link is reported, not followed.                                                                                                            |
| `~/.flutterdeck/ports.json.lock`             | write and read (daemon)                           | Same as `startup.lock`.                                                                                                                                                                                                                    |

The home folder `~/.flutterdeck` itself is the user's own. A link there is their choice and is followed.

Error messages that reach Claude or the dashboard name a file by its project-relative path. Before they are cut or masked, the project folder becomes `<project>` and the home folder becomes `~`.
