Pitdeck M5: public release

Any Flutter developer can install Pitdeck from the README and see their app's database, logs and reload buttons next to Claude in under five minutes.

Problem and users

Today only someone with a clone of our repo can use it

Who

Flutter developers who use Claude Code or Claude Desktop, especially apps with a Drift database.

The job they are doing

Building and debugging a running app with Claude beside them: check the data, read the logs, reload.

Today's pain

Nothing is on npm or pub.dev. The plugin points into our repo folder, so an installed copy can't start. The name "FlutterDeck" breaks Flutter's brand rule and clashes with flutter_deck.

Success measure

A fresh machine with Flutter reaches a working dashboard in under 5 minutes using only the README.

Options

How users get the CLI

Option A: one package, pitdeck

  • npx pitdeck runs our code; we own the name
  • Smallest download; our internal parts stay private
  • Cost: a bundling step; install tests must prove the files are all there
  • Effort: medium

Option B: 11 packages, @project-deck/*

  • No bundling; works as built today
  • Cost: 11 public packages to version together; larger download
  • Risk: npx pitdeck fetches someone else's package unless we also claim it
  • Effort: low now, more later

Recommendation

Option A, because users type one name, download less, and nobody can take that name from us. The plugin then starts that exact version: npx -y pitdeck@0.1.0 mcp.

Security

Our packages will run on other people's machines

Trust boundaries

  • npm and pub.dev: users run what we publish
  • The GitHub repo as the plugin marketplace
  • The release workflow's publish identity

Abuse cases

  • Someone claims pitdeck on npm before us
  • A stolen publish token pushes a bad version
  • A bad change reaches users as a plugin update
  • A dependency hides an install script

Mitigations

  • Your first publish claims both names early
  • Publishing from CI with no stored token; 2FA; provenance on every version
  • Plugin pins one CLI version; auto-update is off by default
  • Install tests run with --ignore-scripts

npm trusted publishing and provenance (docs.npmjs.com/trusted-publishers); pub.dev automated publishing (dart.dev/tools/pub/automated-publishing). Read 10 Nov 2026.

Risks

The main risks

Risk Impact Mitigation
"Pitdeck" turns out to be a registered trademark Another rename after release You check UK, EU and US registers before the first publish
Bundled package misses a file (dashboard, worker, sqlite-wasm) Installed CLI fails where the repo works CI installs the packed tarball on 3 OSes and runs a real query
npx in the plugin fails on Windows No database or log tools for Windows users Windows install test; fall back to cmd /c npx
Users have Google's Dart plugin too Two Dart servers, duplicate tools doctor warns; README says how to turn ours off
The 5-minute goal needs a device and Flutter CI can't prove it QA times it by hand on a clean user account
